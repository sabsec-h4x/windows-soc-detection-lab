---

##  Project Objective

The objective of this project is to understand and demonstrate how a SOC analyst monitors a Windows endpoint and investigates suspicious activity using endpoint telemetry and SIEM detection.

###  End-to-End Workflow

```
Windows 11 ➔ Sysmon ➔ Windows Event Logs ➔ Wazuh Agent ➔ Wazuh Manager ➔ Wazuh Rules & Detection ➔ Wazuh Indexer ➔ Wazuh Dashboard ➔ SOC Analyst Investigation
```

The project progressively demonstrates the complete workflow from generating activity to collecting telemetry, detecting suspicious behavior, investigating alerts, and documenting findings.

### 2. Microsoft Sysmon
Microsoft Sysmon is installed on the Windows endpoint to provide rich endpoint telemetry. Sysmon is configured to monitor:

* Network Connections
* DNS Queries
* File Creation
* Registry Activity

**Log Channel:** `Microsoft-Windows-Sysmon/Operational`

**Verification Command:**

##  Event Investigation Methodology

For every testing scenario, the following 6-step investigation methodology is followed:

* **Step 1 — Identify the Activity:** Determine exactly what activity was generated.
* **Step 2 — Examine Windows Telemetry:** Identify the Windows Event ID and relevant event fields.
* **Step 3 — Examine Sysmon Telemetry:** Identify additional endpoint context such as Process, Parent Process, Command Line, Network Connection, Hash, File, or Registry activity.
* **Step 4 — Analyze Wazuh Alert:** Investigate Rule ID, Alert level, Description, Agent, Timestamp, Event fields, and MITRE ATT&CK mapping.
* **Step 5 — Determine Verdict:** Classify the activity as *True Positive*, *False Positive*, *Benign Activity*, or *Suspicious Activity*.
* **Step 6 — Document Findings:** Document testing methodology, evidence, Windows events, Sysmon events, Wazuh alerts, rule information, MITRE ATT&CK mappings, analyst conclusions, and recommended response.
